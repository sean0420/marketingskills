# 02. 구조와 연동

## 구성

Shine은 HTML 파일 하나(`app/shine.html`)로 된 claude.ai 아티팩트다. 별도 서버가 없고, claude.ai가 제공하는 기능(capability)을 쓴다.

| 기능 | 용도 |
|---|---|
| `db` | 일정·할 일·메모(`items`), 메일 브리핑 결과(`mail/latest`), 미팅 브리핑(`briefs/*`) 저장. 접근 규칙: 소유자(Sean)만 읽고 쓰기 |
| `sample` | Shine AI. 한 줄 해석(빠른 모델), 미팅 메모 정리와 메일 분석(기본 모델) |
| `dictation` | 음성 입력 (한국어) |
| `mcp` | Gmail `search_threads`·`get_thread`·`create_draft`, Google Calendar `list_events`·`create_event` |
| `user` | 사용자 식별 |

저장소에 연결할 수 없는 화면(파일로 직접 열 때 등)에서는 브라우저 로컬 저장소로 대신 동작한다.

## 데이터 구조

모든 항목은 하나의 `items` 컬렉션에 같은 구조로 저장한다. 종류만 다르다.

| 필드 | 예시 | 설명 |
|---|---|---|
| type | task / event / note | 종류 |
| title | 계약서 회신 | 제목 |
| area | work / personal | 업무·개인 |
| priority | high / normal / low | 중요도 |
| date | 2026-11-25 | 마감일 또는 일정 날짜 (내 시간대 기준) |
| time, endTime | 15:00, 16:00 | 일정 시간 (내 시간대 기준) |
| tz, tzDate, tzTime | Asia/Seoul, 2026-11-17, 14:00 | 상대 시간대로 입력한 원래 시각 |
| status, doneAt | open / done | 진행 상태 |
| people, org | ["OOO"], Netflix | 관련 사람·회사 (관련 항목 연결에 사용) |
| attendees | [kim@cjenm.com] | 초대 이메일 |
| gcal | {created, link, meet, attendees, tz} | Google 캘린더 생성 결과 |
| mailUrl | Gmail 링크 | 메일에서 만든 할 일 |
| links | [noteId] | 미팅 메모와 후속 항목 연결 |
| source, raw | Shine 해석, 원문 | 출처와 원문 입력 |
| example | true | 예시 항목 표시 |
| deletedAt | 2026-11-16T15:00:00Z | 보관함으로 옮긴 시각. 값이 있으면 보관함에만 보이고, 30일이 지나면 앱이 열릴 때 영구 삭제 |

`mail/latest` 문서: `checkedAt`, `checkedDay`, `me`(내 주소), `seen`(스레드별 마지막 메시지 id), `results[]`(id, kind, priority, tag, isNew, addedAt, why, action, due, area, subject, from, url), `dismissed[]`(넘긴 스레드), `personalEmail`.

## 한 줄 입력 처리 순서

1. 로컬 해석기가 즉시 결과를 보여준다 (오늘/내일/요일/다음주 X요일/M월 D일/시각/시간대/이메일/중요 키워드).
2. 동시에 Shine AI가 더 정확한 해석을 보낸다. 도착하면 미리보기를 바꾼다.
3. 사용자가 Enter로 확인해야 등록된다. AI 결과를 기다리지 않고 바로 등록할 수도 있다.

## 시간대 처리

- 일정은 항상 내 시간대(달라스) 기준 `date/time`으로 저장한다. 상대 시간대로 입력했다면 원래 시각을 `tz/tzDate/tzTime`에 같이 남긴다.
- 변환은 브라우저의 `Intl` 시간대 데이터로 계산한다. 서머타임 경계도 반영된다.
- Google 캘린더 생성 시 상대 시간대가 있으면 그 시간대(예: Asia/Seoul)로 만든다. Google이 각자의 시간대로 보여준다.

검증 예: 한국 11/17(화) 14:00 = 달라스 11/16(월) 23:00, 한국 3/9 10:00 = 달라스 3/8 20:00 (CDT 시작 직후).

## 메일 브리핑

1. Gmail에서 최근 4일 받은편지함(광고·소셜 제외)과, 2~10일 전 내가 마지막으로 보낸 스레드를 가져온다.
2. Shine AI가 답장 필요 / 후속 / 마감으로 분류하고, 중요도(높음·보통·낮음)와 태그(견적 요청·긴급·계약·결제·미팅·문의·후속·참고), 이유, 할 일 제목을 만든다. 뉴스레터, 광고, 무관한 콜드 영업은 뺀다.
   - 안전장치 규칙: 제목·미리보기에 quote, RFQ, RFP, rate card, 견적, 단가 등이 있으면 무조건 높음 + 견적 요청. urgent, ASAP, 긴급, 오늘까지 등이 있으면 높음 + 긴급. 마감이 2일 이내면 높음.
3. 결과는 `mail/latest`에 저장한다. 하루 첫 접속(오전 5시 이후)에 자동 실행되고, "지금 확인"으로 다시 돌린다.

## 실시간 반영

- 데이터는 저장소의 실시간 구독으로 받는다. 다른 기기에서 바꾸면 보통 몇 초 안에 반영되고, 실시간 연결이 안 되면 약 30초마다 다시 가져온다.
- 화면 오른쪽 위 표시: 실시간(초록) / 연결 중(노랑) / 오프라인(빨강). 누르면 즉시 새로 고친다.
- 화면을 다시 켜거나 앱으로 돌아오면 시계, 타임라인, 인사말을 다시 그린다.
- 메일 실시간 감시: 화면이 켜져 있는 동안 10초마다 Gmail 받은편지함(최근 4일)을 가볍게 읽는다. 스레드마다 마지막 메시지 id를 `mail/latest.seen`에 기억해 두고, 새로 오거나 새 답장이 달린 스레드만 Shine AI로 분석해 목록에 더한다(NEW 배지). 바뀐 게 없으면 AI를 부르지 않는다.
- 내가 마지막으로 답장한 스레드는 감시 중에 자동으로 목록에서 빠진다.
- 전체 재분석(답 기다리는 후속 메일 포함)은 7~21시 사이 1시간마다, 또는 "전체 다시 분석" 버튼으로 실행한다.
- Gmail 오류가 나면 30초에서 최대 2분까지 간격을 늘리고, 연결·권한 문제면 감시를 멈추고 안내한다.
- 편집 창에서 입력 중이거나 항목을 밀고 있을 때는 다른 기기의 변경이 화면을 덮어쓰지 않도록 갱신을 미룬다.
- 앱 코드가 새로 배포되면 열린 화면에 자동으로 적용된다.

## Google 캘린더 읽기 동기화

- 기본 캘린더(primary)의 일정을 `list_events`로 읽는다. 범위는 보고 있는 달의 월간 그리드(6주) + 오늘 전후, 최대 1,250개.
- 화면이 켜져 있으면 30초마다, 화면 복귀 시, 보기 이동 시(범위 밖이면) 다시 읽는다. 바뀐 게 없으면 화면을 다시 그리지 않는다.
- 저장소에 복사하지 않고 화면에서만 합친다. 그래서 Google에서 일정이 바뀌거나 지워지면 Shine에도 그대로 반영된다.
- 제외: 취소된 일정, 내가 거절한 일정, Shine 항목과 제목·날짜·시간이 같은 일정(중복).
- 종일 일정은 끝 날짜 전날까지 날마다 표시한다(최대 14일).
- Google 일정은 읽기 전용이다. 밀어서 삭제와 별 표시가 없고, 누르면 참석자·설명·Meet 링크·Google 캘린더 링크와 "준비 할 일 추가"가 나온다.

## 미팅 준비 카드

- 오늘 일정 중 2시간 안에 시작하거나 진행 중인 첫 미팅을 첫 화면 숫자 요약 아래에 띄운다.
- 관련 정보 찾기: 참석자 이메일의 외부 도메인(gmail 같은 개인 도메인 제외)과 회사·사람 이름으로 Shine의 할 일·메모, 메일 브리핑 항목을 찾는다.
- 브리핑: 미팅 30분 전 자동으로, 또는 버튼으로 만든다. 참석자 도메인으로 최근 60일 Gmail 스레드 8개를 읽고, 관련 할 일과 함께 Shine AI에 넣어 맥락·챙길 것·열린 일을 만든다. 결과는 `briefs/b_<일정 id>`에 저장해 다른 기기에서도 다시 만들지 않는다.

## 답장 초안

1. 메일 브리핑 항목의 [답장 초안]을 누르면 `get_thread`로 스레드의 최근 6개 메시지를 읽는다. 인용된 이전 메일(On ... wrote:, >)은 잘라낸다.
2. Shine AI가 상대 언어로 초안을 쓴다. 규칙: 인사 → 감사 → 핵심 → 다음 단계 → 마무리, 서명 제외, em dash 금지(남아 있으면 쉼표로 바꿈), 모르는 사실은 [대괄호]. 견적 요청이면 필요 정보 확인, 답 없는 스레드면 짧은 후속, 무관한 영업이면 정중한 거절.
3. 받는 사람, 제목, 본문을 고친 뒤 `create_draft`로 마지막 메시지에 대한 답장으로 저장한다(`replyToMessageId`, Gmail 서명 포함).
4. Shine은 메일을 보내지 않는다. 발송은 Gmail에서 직접 한다. 저장한 메일은 브리핑에 "초안 저장됨 ✓"으로 표시된다.
5. 그룹 주소(sales@ 등)로 받은 메일은 실제 보낸 사람이 가려질 수 있어 받는 사람 확인 안내를 띄운다.

## 사람·회사 타임라인

- 목록: Shine 항목의 `org`(회사)와 `people`(사람), 캘린더 참석자(이메일, 외부 도메인은 회사로 묶음), 메일 브리핑 보낸 사람에서 자동으로 만든다. 같은 이름(소문자)은 하나로 합친다. 최근 활동순.
- 진입: "사람" 탭, 또는 화면 어디서든 밑줄 친 회사명·사람 이름·참석자·보낸 사람을 누른다.
- 타임라인: 처음 열 때 Gmail(`{from:도메인 to:도메인} newer_than:365d`, 20스레드)과 캘린더(`list_events` fullText=도메인, 지난 1년~앞으로 90일)를 찾아오고, 화면에 이미 있는 일정·Shine 항목·메일 브리핑과 합쳐 중복을 빼고 최신순 월별로 보여준다. 앞으로의 일정은 그라데이션 점.
- Shine 관계 요약: 타임라인 최근 40건을 Shine AI에 넣어 관계 현황, 진행 중인 일, 다음 할 일을 만든다. 기록에 없는 내용은 만들지 않는다.
- 한계: 도메인이 없는 사람(이름만 있는 경우)은 이름으로만 찾아서 정확도가 낮다. 같은 사람이 이름과 이메일로 두 번 보일 수 있다.

## 아침 자동 브리핑

- 예약 작업 "Shine 아침 브리핑" (id `trig_017HKz7vnQhLQ73pTmH5HFNu`, 평일 06:43 America/Chicago, 실행마다 새 세션, 완료 시 푸시 알림).
- 작업 내용: 오늘 Google 캘린더 일정, 최근 24시간 메일과 답 기다리는 스레드, Shine의 마감·중요 할 일을 읽어 `briefs/morning_<YYYY-MM-DD>` 문서로 저장한다. 메일과 일정은 읽기만 하고 절대 보내거나 바꾸지 않는다.
- 앱은 오늘 날짜의 브리핑 문서를 실시간 구독해서, 저장되는 순간 첫 화면 맨 위에 카드로 띄운다. [확인했어요]를 누르면 그날은 숨긴다(기기별).
- 문서 형식: `{date, createdAt, headline, focus[], meetings[{time,title,meet}], mails[{subject,from,why,priority,url}], tasks[{title,due,priority}]}`.
- 주의: 예약 작업에 Gmail과 Google Calendar 커넥터가 연결돼 있어야 메일과 일정을 읽을 수 있다. claude.ai의 예약 작업 화면에서 추가한다.

## Google 캘린더 미팅 생성

`create_event` 호출 값: `summary`, `startTime`, `endTime`, `timeZone`, `attendees[{email}]`, `addGoogleMeetUrl`, `description`. 결과에서 Meet 링크와 캘린더 링크를 찾아 항목에 저장한다.

**미확인:** 실제 생성 결과 형태는 아직 확인하지 못했다. 첫 미팅을 만든 뒤 Meet 링크가 표시되는지 확인해야 한다.
